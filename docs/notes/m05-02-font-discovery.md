# M05.02 — Font discovery and role selection

**Status:** done; Linux discovery/loading and product startup are validated.
Other platforms retain an explicit unsupported adapter.

## Behavior and configuration

`src/text/fonts` resolves three independent roles: body, tag, and console.
Each role owns its own FreeType face and selected path/family metadata.
Initialization is all-or-nothing and cleans up partial role initialization.

- `font_families` remains the ordered body stack.
- `tag_font_families` and `console_font_families` are now supported; omitted
  role stacks inherit the fully resolved body stack.
- `font_path` is an optional explicit file override for every role and selects
  face index zero. A missing or invalid explicit file is an error and is never
  replaced with a discovered font.
- Config staging schema version is 2. Paths, family counts, family lengths, and
  staged characters are validated. Existing generated files with schema 1 fail
  loudly and are regenerated by the build tool.

Linux family lookup uses fontconfig 2.18.3 (`src/text/fontconfig`). A named
family is accepted only when a returned family name matches case-insensitively;
this prevents fontconfig's closest-match behavior from bypassing the configured
order. Generic `monospace`, `sans`, `sans-serif`, `serif`, `system-ui`, and
`emoji` requests accept fontconfig's selected font. Every discovered or direct
path is validated by opening it with FreeType before initialization succeeds.

`src/fonts.odin` connects the compiled configuration to product startup and
logs each selected role/path/face index. Font failure is nonfatal while the
rectangle renderer remains the fallback. Cleanup destroys faces before the
FreeType library and releases the referenced fontconfig configuration. The
process-global default config is referenced but never replaced, and `FcFini`
is not called. Tests instead use explicit isolated configurations.

## Test fixture

`tests/integration/textdeps/fixtures/FixtureMono.ttf` is a 31,852-byte subset
of Noto Sans Mono containing ASCII and U+0301. It was produced with the pinned
HarfBuzz `hb-subset` from the installed Noto font, retaining name and layout
metadata. The upstream project is
https://github.com/notofonts/latin-greek-cyrillic; the SIL OFL 1.1 text is in
`fixtures/LICENSE.txt`. No reserved font name is declared by that license.

Each native test creates a unique temporary directory, writes a fontconfig
file containing only the fixture directory and a sandbox cache directory, and
removes the sandbox afterward. Setup failure returns before any default
fontconfig path can be used. No user font configuration or session is loaded.

```text
odin run make.odin -file -- text-test
    -> exact FreeType/HarfBuzz/ICU/fontconfig/glslc pins; 8/8 native tests
```

The existing build tool accepts `--config=PATH`; the separated `--config PATH`
form shown in older documentation was not changed by this task.

## Limits and next task

- Only Linux performs discovery. Windows cross-compiles but reports
  `.Unsupported` at runtime; Windows/Wine discovery was not run. macOS and other
  platforms use the same explicit unsupported adapter.
- Explicit paths currently select face index zero; there are no per-role path
  overrides, variable-font coordinates, style/weight selection, or font reload
  protocol. Those are not claimed.
- This task loads and validates faces but does not render text or implement
  per-cluster fallback. M05.03 should add the bounded glyph atlas/cache with
  identity/face/variation/glyph/pixel-size/render-mode keys, explicit native/GPU
  ownership, eviction, and lifecycle/failure tests.
