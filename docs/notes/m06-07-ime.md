# M06.07 — IME preedit/commit handling

**Status:** implemented for Linux/X11 with headless native validation. The product
creates an X11 input context and normalizes IME events, but has no editable text
consumer or preedit renderer yet. Windows retains ordinary Sokol input; native
Windows IME and Wayland IME are not claimed.

## Core state and commits

`src/core/ime/ime.odin` owns bounded transient preedit state. begin/update/caret/
done/cancel transitions never edit a document. Updates validate UTF-8 and the
Unicode-scalar caret, allocate the replacement before releasing the old text, and
leave the previous snapshot intact on failure. Snapshots are borrowed until the
next transition. The default text limit is 64 KiB and destruction releases the
owned allocation.

`input.Preedit` and `input.Commit_Text` distinguish composition from complete
commits. Commit text is borrowed only during dispatch. `editing.Commit_Text`
validates the entire UTF-8 string and inserts or replaces the selection through
one `.Typing` transaction, rather than emitting one transaction per scalar.
Empty commits are no-ops; invalid scalars change nothing. Keybind resolution
keeps preedit non-editing, applies the existing AltGr/command-modifier policy to
commits, and exposes the complete commit to the ordinary editing dispatcher.

## X11 adapter and Sokol decision

`src/platform/x11ime` uses the existing Sokol display/window, negotiates preedit
callbacks when available, and falls back to PreeditNothing/StatusNothing. It
handles focus, MappingNotify refresh, XFilterEvent consumption, XmbLookupString,
bounded commit allocation, and preedit start/draw/caret/done callbacks. Payloads
and errors are borrowed only for the notification callback. Wide-character
preedit is rejected explicitly as unsupported rather than decoded incorrectly.

The M00.05 integration decision is resolved with a narrow local patch to the
pinned Sokol C revision: `third_party/patches/sokol-app-x11-ime.patch` adds a
pre-dispatch filter. Filtered-out keys produce no Sokol event; XIM-processed keys
retain Sokol key-down behavior but suppress the duplicate legacy CHAR event.
`make.odin` applies the patch reproducibly and rebuilds the Sokol app library when
the hook is introduced. The patch is Linux-only and does not alter Windows builds.

Product startup initializes bounded preedit state and the X11 adapter; failure is
reported and leaves ordinary Sokol input active. Cleanup unregisters the hook
before destroying the IC/IM. Current product consumption logs normalized preedit
and commit events, matching the existing demo's logging-only input dispatch.

## Tests and validation

Three core IME tests cover Unicode snapshots, caret updates, done/cancel/reuse,
invalid UTF-8/carets, size limits, and atomic failure behavior. Two editing tests
cover multi-scalar replacement, one-step undo/redo, empty commits, and invalid
text. Input/keybind tests cover event diagnostics, union round trips, modifier
policy, preedit separation, and a resolved `é中` commit in the transaction
sequence.

`tests/integration/ime` injects preedit callbacks directly and uses real XTEST
key events under isolated Xvfb to verify dead-acute + e and plain a produce exactly
`éa` through the native adapter. A real IM server did not deliver preedit callbacks
in this environment.

## Limits and next task

- No real desktop IM server, real preedit rendering, real Windows IME, or Wayland
  IME was exercised. Wide-character X11 preedit remains an explicit unsupported
  input form.
- The product demo does not yet insert commits into a document or draw preedit;
  M06.09 owns product text-input consumption and typed-text rendering.
- M06.08 should add clipboard interoperability tests with separate external
  applications, including Unicode and large transfers, without touching the real
  user clipboard.
